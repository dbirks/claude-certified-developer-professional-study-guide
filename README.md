# Claude Certified Developer – Professional (CCDV-P) Study Guide

A source-cited study guide for the **Claude Certified Developer – Professional (CCDV-P)** exam. It is live at
<https://dbirks.github.io/claude-certified-developer-professional-study-guide/>. Every factual claim links to a
citation with a verbatim quote from an official or standards source, so you can check the source instead of trusting
the summary. This project is **not affiliated with, endorsed, or reviewed by Anthropic**. `Exam lens` boxes are the
author's editorial inference about what a scenario might test — they are not official exam content.

## What's inside

- **25 skill chapters across 8 domains**, following the official blueprint in Exam Guide v1.0 (effective November
  2026), retrieved and verified against the primary source on 2026-11-19. Chapter scope and headings track the
  guide's skill descriptions; `research/exam-guide.md` holds the extracted blueprint.
- **Reference appendix**: Messages API and tool-use quick reference, "choosing the right building block," and a
  glossary with operational formulas (`/reference/api-reference/`, `/reference/building-blocks/`,
  `/reference/glossary/`).
- **Tap-to-open citations.** Each claim carries a numbered marker that opens a popover with the source title, URL,
  tag, and the exact quoted passage. Chapter end shows a numbered Sources list.
- Per-domain weights, self-check questions, callouts for common mistakes and version-sensitive facts, and CSS/SVG
  flow and sequence diagrams.

## How the content was produced and checked

1. **Research packet per skill.** `research/packets/<slug>.md` holds the notes; `research/citations/<slug>.yaml`
   holds one entry per citable fact, each with a **verbatim quote** copied from the source page. Format is
   specified in `research/PACKET_FORMAT.md`.
2. **Automated quote verification.** `scripts/verify-quotes.mjs` re-fetches every cited URL and checks that the
   quote appears on the page (whitespace, quote-mark and dash normalization; PDFs are text-extracted with `pypdf`
   via `uvx`). Per-skill results land in `research/quote-check/<slug>.json`. A non-verbatim quote fails the check.
3. **Drafting from packets only.** A drafting worker writes the chapter from its packet and citation file. Anything
   not in the packet does not appear in the chapter.
4. **Independent claim-by-claim review.** A second AI model reviews the chapter against its cited sources, edits it,
   and records every change in `research/fact-check/<slug>.md`; `research/fact-check-log.md` indexes the logs and
   reviewers.
5. **Coverage matrix.** `research/coverage-matrix.md` (generated by `scripts/build-research-index.mjs`) shows, per
   skill: packet exists · citation count · quotes verified ok/total · chapter status · fact-check log. At the last
   regeneration: 255 unique source URLs and 1,105 citation entries.

**Reviewers are AI models, not human subject-matter experts.** The fact-check logs name each reviewer (Gemini 4
Hydrogen, GPT-6.x via Codex). Automated quote checks prove a quote is on the page; they do not prove the
surrounding interpretation is right.

## Stack and why

| Choice | Why |
| --- | --- |
| Astro 7 + MDX, static output | Content-heavy site, no server. Chapters are plain MDX files. |
| Real static HTML per page | Refresh and deep links work on GitHub Pages with no 404 fallback. |
| Pagefind | Static, client-side full-text search with no backend or bundle bloat. |
| Shiki at build time | Code highlighting costs nothing at runtime. |
| No UI framework | Client behavior is small plain-TypeScript modules in `src/scripts/` (one `init*()` each); the site ships minimal JS. |
| Plain CSS, one file per concern | `src/styles/` splits tokens, layout, prose, code, TOC, citations, print; all colors and fonts come from `tokens.css`. |
| Gelato visual system | Young Serif (display), Manrope (body/UI), DM Mono (code), Lucide icons, from the owner's design handoff in `docs/design/`. Fonts are self-hosted via `@fontsource`. |

`docs/ARCHITECTURE.md` is the contract: DOM ids/classes, TOC markup, MDX component API, CSS file ownership, design
tokens. Do not rename contract selectors — the client scripts and the Playwright suite depend on them.

## Local development

Requires Node 22.23.4+ and pnpm 12 (`packageManager` field).

```bash
pnpm install
pnpm dev        # dev server
pnpm build      # astro build && pagefind --site dist
pnpm preview    # serve the built dist/
```

Build environment variables:

| Variable | Effect |
| --- | --- |
| `BASE_PATH=/repo/` | Base URL for project Pages builds. Internal links must use `url()` from `src/lib/site.ts`, never hard-coded `/` paths. |
| `SITE_URL` | Site origin (default `https://dbirks.github.io`). |
| `CCDVP_ONLY=<slug>` | Build only that chapter plus the introduction, so parallel work doesn't block your build. |
| `CCDVP_DEMO=1` | Include `content/reference/component-demo.mdx`, the test page with every component. |
| `CCDVP_PRACTICE=1` | Include the unpublished practice question pages in `content/practice/`. |

Checks:

| Command | What it does |
| --- | --- |
| `pnpm check` | `astro check` — TypeScript and Astro type errors. |
| `pnpm check:citations` | Validates every `research/citations/*.yaml` and that each `<Cite id="…">` in content resolves. |
| `pnpm check:links` | Walks the built site (default `dist`, pass another dir) and fails on broken internal links, missing `#fragment` targets, and duplicate element ids. Needs `BASE_PATH` matching the build. |
| `pnpm verify:quotes` | Re-fetches all cited URLs and confirms every quote is verbatim. Needs network access; `uvx` for PDF sources. |
| `pnpm test:e2e` | Playwright, desktop (1366×900) and mobile (390×844, touch) projects, run against a production build served under `/ccdvp-test/`. Covers: no horizontal overflow, subpath assets and links, theme toggle persistence, citation popover content, TOC collapse/expand persistence, deep-link active state, search navigation, and drawer gestures plus keyboard-only focus handling. First run needs `pnpm exec playwright install --with-deps chromium`. |

## Editing content

Chapters are MDX files in `content/` (outside `src/`): one file per skill under the domain directory, plus
`00-introduction.mdx` (`kind: intro`, rendered on the home page) and `reference/<slug>.mdx`. Skill URLs are
`/<domain-slug>/<skill-slug>/`; reference URLs are `/reference/<slug>/`; trailing slash always.

Frontmatter (schema in `src/content.config.ts`):

```yaml
title: "Reliability Patterns for Claude Tool Calls"
summary: "One-sentence chapter lede, shown in the chapter hero."
kind: skill            # skill | reference | intro
skill: "2.1"           # required when kind: skill
slug: reliability      # syllabus slug for skills; URL segment for reference pages
order: 0               # ordering for reference pages
status: fact-checked   # draft | fact-checked
lastReviewed: "2026-11-19"
citations: reliability # citation file stem in research/citations; defaults to slug
```

MDX components are injected globally — no imports needed in chapters:

| Component | Use |
| --- | --- |
| `<Cite id="F3" />` / `<Cite id="F3 F7" />` | Citation marker; resolves to the numbered source in that chapter's citation file. |
| `<Callout type="mistake\|version\|note" title="…">…</Callout>` | Inline warning block. |
| `<ExamLens>…</ExamLens>` | Labeled editorial inference about what the exam may test. |
| `<SelfCheck question="…">answer</SelfCheck>` | Reveal-the-answer prompt. |
| `<Figure caption="…">…</Figure>` | Wraps a diagram, table, or image with a caption. |
| `<Flow steps={[…]} direction="vertical" />` | Box-and-arrow pipeline. |
| `<Sequence actors={[…]} messages={[…]} />` | Sequence diagram (crash/recovery, retries). |

To add a citation, append an entry to `research/citations/<slug>.yaml`:

```yaml
- id: F12                      # unique within the file; chapter cites as <Cite id="F12" />
  claim: "The statement the chapter makes, in our own words."
  tag: FACT                    # FACT documented | REC recommendation | VER version-sensitive | STD standard/spec
  url: https://platform.claude.com/docs/en/api/errors   # exact deep link, plus #anchor when available
  title: "Claude API errors"
  source: anthropic-docs       # anthropic-docs | anthropic-engineering | anthropic-research | claude-code-docs | mcp-spec | standard | other
  quote: "verbatim text copied from the page"
  accessed: 2026-11-19
  version_note: "Optional: what could change."
```

The `quote` must be **verbatim** — `verify:quotes` fails otherwise. After editing, run
`pnpm check:citations && pnpm verify:quotes`, and regenerate the indexes with
`node scripts/build-research-index.mjs`.

## Deployment

GitHub Actions (`.github/workflows/deploy.yml`) builds and publishes on every push to `main`, plus manual dispatch.
The build job: checkout → pnpm + Node 24 → `actions/configure-pages` → `pnpm install --frozen-lockfile` →
`pnpm check:citations` → `pnpm check` → `pnpm build` (with `BASE_PATH` and `SITE_URL` from configure-pages) →
`pnpm check:links` → Playwright E2E on Chromium (desktop and mobile, subpath) → upload `dist` as the Pages artifact.
A separate `deploy` job publishes it with `actions/deploy-pages`.

In the repository: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

## Known limitations

- **Version-sensitive facts drift.** Model names, rate limits, pricing, and beta features were checked on
  2026-11-19 against the sources cited in each chapter. Re-verify before relying on them.
- **AI review, not SME review.** Independent review was performed by other AI models. There is no human
  subject-matter-expert sign-off.
- **Practice question pages are unpublished.** They exist in `content/practice/` and build only with
  `CCDVP_PRACTICE=1`.
- **Gelato surfaces are partially unreviewed.** The design handoff in `docs/design/` covers the chapter, drawer,
  citation, and practice frames listed in `docs/ARCHITECTURE.md`. The home page, search dialog, and diagrams were
  extended to match the system without their own design review.
